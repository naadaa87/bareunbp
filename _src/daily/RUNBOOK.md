# 바른혈압 매일 발행 운영 문서

매일 아침 예약 작업이 이 문서대로 글을 발행한다. 사람이 손으로 할 때도 같은 순서를 따른다.

## 한 번의 실행에서 하는 일

1. **오늘 글 발행** — 전날 써 둔 오늘 날짜 글을 사이트에 넣고 올린다. 몇 분이면 끝나서 오전 9시 30분 무렵 사이트에 반영된다.
2. **내일 글 준비** — 내일 날짜 글을 조사해서 쓰고, 점검을 통과하면 저장소에 올려 둔다. 파일 이름의 날짜가 내일이라 사이트에는 아직 보이지 않는다(예약 발행).

오늘 글이 없으면(첫날, 전날 실패 등) 오늘 글부터 써서 발행하고, 이어서 내일 글을 쓴다.

## 0. 준비

```bash
cd <저장소>                      # naadaa87/bareunbp
git pull --rebase -q
cd _src/gen
python3 daily.py status          # 발행·예약 현황, 남은 주제 수
```

- 저장소가 없으면 add_repo(owner=naadaa87, repo=bareunbp, access=push)로 붙이고 안내받은 명령으로 받는다.
- 날짜는 언제나 **한국 시간** 기준이다. `daily.py`가 알아서 계산한다.

## 1. 오늘 글 발행

```bash
python3 daily.py next            # already_written에 오늘 파일이 있는지 본다
```

**오늘 파일이 있으면**

```bash
python3 daily.py check ../daily/posts/<오늘 파일>.py
python3 build.py                 # 사이트 전체 다시 생성 (오늘 글 포함)
python3 check_site.py            # 깨진 링크 0, 메타 문제 0 이어야 함
cd ../.. && git add -A && git commit -m "발행: <글 제목>" && git push origin main
```

- 커밋 작성자는 `git -c user.name="naadaa87" -c user.email="naadaa87@users.noreply.github.com" commit ...`로 한다.
- push가 거절되면 `git pull --rebase` 후 다시 `build.py`를 돌리고 한 번 더 올린다.
- 바뀐 것이 없다면(이미 발행됨) 커밋하지 않고 넘어간다.

**오늘 파일이 없으면** 아래 2번 절차로 오늘 날짜 글을 쓴 뒤 위 명령으로 발행한다.

## 2. 글 쓰기 (내일 글 기준)

```bash
python3 daily.py next --date <내일 날짜>
```

나온 `topic`(주제·키워드·독자·방향·연결할 글)과 `file`(만들 파일 경로)대로 쓴다.

### 2-1. 조사

- WebSearch로 먼저 찾고, 검색 결과에 나온 주소만 WebFetch로 읽는다. 주소를 지어내지 않는다.
- **출처는 2곳 이상, 실제로 읽은 것만** 쓴다. 우선순위:
  1. 대한고혈압학회(koreanhypertension.org), 대한당뇨병학회, 한국지질동맥경화학회, 대한뇌졸중학회, 대한심장학회
  2. 질병관리청·국가건강정보포털(health.kdca.go.kr), 식품의약품안전처·식품안전나라·의약품안전나라(nedrug.mfds.go.kr), 국민건강보험공단
  3. 대학병원 질환 정보(서울아산병원·서울대병원 등), WHO, 미국심장협회(AHA)
  4. 위 기관 자료를 보도한 언론 기사 — 기관과 자료 이름을 함께 적는다
- 블로그, 쇼핑몰, 제품 광고, 출처 없는 카드뉴스는 근거로 쓰지 않는다.
- 숫자는 연도와 함께 쓴다(“2025년 국민건강영양조사에서 …”). 확인 못 한 숫자는 쓰지 않는다.
- 저장소에 이미 있는 출처 상수(`articles.py`의 KSH2026, KDCA, WHO_NA, `articles3a.py`의 KDCA_HTN, KNHANES2025, FACT2026, `food.py`의 MFDS_EATOUT 등)를 그대로 가져다 써도 된다. 그 내용과 맞는 사실만 인용한다.
- 주제가 근거를 찾기 어렵거나 위험하면 `plan.json`에서 그 주제의 `"status": "skip"`, `"note": "이유"`를 달고 다음 주제로 넘어간다.

### 2-2. 파일 만들기

- 파일: `_src/daily/posts/YYYY-MM-DD-slug.py` (날짜 = 발행일, slug = 계획표의 slug)
- 형식은 `templates/`의 견본과 이미 발행된 글(`posts/`)을 그대로 따른다.
  - `article` 건강정보: cat, title, summary, keywords, tags, kind, certainty, target, body, faq
  - `food` 음식·식단: title, summary, keywords, kind, certainty, target, body, faq
  - `factcheck` 팩트체크: claim, verdict(ok·partial·insuff·contra·doctor), summary, conditions, body, srcs
  - `recipe` 레시피: name, time, serves, desc, ingredients, steps, tips
- 선택: 용어사전에 넣을 `GLOSSARY = [(용어, 영문, 설명, 링크)]`, 자주 묻는 질문 `FAQ = [(분류, 질문, 답)]`, 고혈압 소식 `NEWS = [(날짜, 제목, 내용, 출처, [(링크, 이름)])]`

### 2-3. 검색에 잘 걸리게

- **제목**: `핵심 키워드 — 부제` (16~60자). 사람들이 실제로 치는 말을 앞에 둔다. 예: `혈압 140/90 — 고혈압일까, 다시 재야 할까`
- **요약**(summary): 60~170자. 첫 문장에 답이나 핵심 숫자. 검색 결과 설명으로 그대로 쓰인다.
- **첫 단락**은 `answer("...")`로 질문에 바로 답한다(두세 문장).
- **소제목**(`<h2>`) 4개 이상. 소제목도 검색어처럼 쓴다(“언제 병원에 가야 하나”).
- **자주 묻는 질문** 3~5개. 실제 검색창에 치는 질문 그대로, 물음표로 끝낸다.
- **사이트 안 링크 3개 이상** — 관련 글, 도구(/check7/, /tools/sodium/ 등)로 이어 준다. 지금 사이트에 있는 페이지만 링크한다(점검이 막는다).
- 표·체크리스트를 적어도 하나 넣는다. 본문은 FAQ 포함 1,800자 이상.

### 2-4. 쓰는 방식 (사람이 쓴 글처럼)

- ‘~습니다’체. 짧은 문장, 한 단락에 한 가지 이야기.
- 쓰지 않는 말: ‘알아보겠습니다’, ‘살펴보겠습니다’, ‘결론적으로’, ‘여러분’, ‘매우 중요합니다’, 이모지, 느낌표 남발.
- 독자(persona)가 처한 장면에서 시작한다. 같은 말을 되풀이하지 않는다.
- 아는 척보다 정확하게. 근거가 약하면 약하다고 쓴다.

### 2-5. 의료 안전 규칙 (반드시)

- 진단, 처방, 개인별 판정을 하지 않는다. 약 이름은 일반 정보로만 다루고 **용량을 지시하지 않는다**.
- 약을 끊거나 바꾸라고 하지 않는다. 언제나 “의료진·약사와 상의”로 맺는다.
- ‘완치’, ‘특효’, ‘혈관 청소’, ‘약 없이’, ‘이것만 먹으면’ 같은 표현을 쓰지 않는다.
- 응급 신호가 있는 주제(두통, 흉통, 갑작스러운 고혈압 등)는 119 안내를 넣는다(`emergency()` 사용 가능).
- ‘전문의 감수’ 같은 말을 본문에 쓰지 않는다. 감수 표시는 사이트가 붙인다(지금은 ‘의료진 감수 예정’).
- 특정 제품·병원을 추천하거나 순위를 매기지 않는다.

### 2-6. 점검

```bash
python3 daily.py check ../daily/posts/<파일>.py     # 통과해야 함
python3 daily.py preview --date <그 날짜>           # 그 날 기준으로 사이트 전체를 임시 폴더에 만들어 점검
```

- 점검이 지적한 것은 모두 고친다. 금지 표현을 피해 가려고 뜻을 바꾸지 말고 문장을 다시 쓴다.
- 미리보기 파일을 한 번 열어(또는 Playwright로 캡처해) 표·목록이 깨지지 않았는지 본다.

### 2-7. 올리기

- **내일 글**: 파일만 추가해 커밋한다 — `git add _src/daily && git commit -m "예약: <제목> (<날짜> 발행)" && git push origin main`. 사이트 파일은 다시 만들지 않는다.
- **오늘 글**: 1번의 발행 명령(build → check_site → 커밋·push).

## 계획표가 줄어들면

`daily.py status`의 `topics_left`가 14개 아래로 내려가면, 실행 끝에 `plan.json` 맨 뒤에 새 주제를 20개 더한다.

- 이미 있는 글(`/info/`, `/food/`, `/factcheck/`, `/food/recipes/`)과 겹치지 않게
- 요일 비율: 건강정보 4, 음식·식단 1, 팩트체크 1, 레시피 1
- 실제 검색어 중심(“혈압 ○○ 이유”, “○○ 혈압에 좋은가”), 계절 주제는 `after`/`before`로 기간 지정
- 혈압과 함께 관리하는 혈당·콜레스테롤·콩팥 주제는 넣되, 혈압과의 관계를 중심에 둔다

## 하지 않는 것

- `posts/`, `plan.json` 말고 다른 사이트 코드·디자인·정책 페이지를 고치지 않는다(꼭 필요하면 고치지 말고 보고만 한다).
- 이미 발행된 글을 지우거나 날짜를 바꾸지 않는다. 고칠 것이 있으면 내용만 고치고 정정 사항은 보고한다.
- 하루에 두 편 이상 발행하지 않는다(밀린 글을 한꺼번에 올리지 않는다).
