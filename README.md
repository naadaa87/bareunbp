# 바른혈압 홈페이지 · 배포 가이드

이 폴더가 그대로 웹사이트입니다. 빌드(변환) 과정이 없어서 GitHub에 올리고 Cloudflare Pages에 연결하면 바로 열립니다.

---

## 1단계. GitHub에 올리기 (10분)

1. https://github.com 로그인 → 오른쪽 위 **+** → **New repository**
2. Repository name: `bareunbp` (아무 이름이나 됩니다) → **Private** 선택 → **Create repository**
3. 만들어진 화면에서 **uploading an existing file** 링크 클릭
4. 이 폴더 안의 **모든 파일과 폴더**를 드래그해서 올립니다.
   - `index.html`, `assets`, `functions`, `info`, `factcheck`, `_headers`, `_redirects`, `schema.sql` 등 전부
   - 폴더째로 드래그하면 안의 파일까지 올라갑니다. 파일이 60개가 넘으므로 한 번에 안 되면 폴더 단위로 나눠 올리세요.
5. 아래 **Commit changes** 클릭

---

## 2단계. Cloudflare Pages 연결 (10분)

1. https://dash.cloudflare.com 로그인 → 왼쪽 **Workers & Pages** → **Create** → **Pages** 탭 → **Connect to Git**
2. GitHub 계정 연결 → 방금 만든 저장소 선택 → **Begin setup**
3. 설정값:
   - Project name: `bareunbp` (이게 임시 주소가 됩니다: `bareunbp.pages.dev`)
   - Production branch: `main`
   - Framework preset: **None**
   - Build command: **비워둠**
   - Build output directory: `/` (슬래시 하나)
4. **Save and Deploy** → 1~2분 뒤 `https://bareunbp.pages.dev` 에서 사이트가 열립니다.

여기까지 하면 **사이트의 모든 페이지와 7일 기록·리포트 도구가 정상 동작**합니다.
기록은 이용자의 브라우저에만 저장되므로 서버가 없어도 됩니다.
문의·질문·구독 폼만 "접수 서버가 아직 연결되지 않았습니다 → 이메일로 보내기"로 안내됩니다.
3단계를 마치면 폼이 데이터베이스에 저장됩니다.

---

## 3단계. 데이터베이스(D1) 연결 (15분)

문의·커뮤니티 질문·뉴스레터 구독·팩트체크 요청, **회원가입·자유게시판·저장한 글**, 그리고 관리자 콘솔의 기록(감수·정정 이력·공지·통계)을 저장하는 단계입니다. 이 단계를 마쳐야 회원가입과 게시판이 열립니다.

### 3-1. 데이터베이스 만들기
1. Cloudflare 대시보드 → **Workers & Pages** → **D1 SQL Database** → **Create**
2. 이름: `bareunbp` → **Create**
3. 표(테이블)는 따로 만들지 않아도 됩니다. 사이트가 첫 접속 때 필요한 표를 자동으로 만들고, 이전 버전 데이터베이스에도 새로 필요한 칸을 자동으로 추가합니다. (`schema.sql`은 참고용입니다.)

### 3-2. 사이트와 연결하기
1. **Workers & Pages** → `bareunbp` 프로젝트 클릭 → **Settings** 탭
2. **Bindings** (또는 Functions → D1 database bindings) → **Add** → **D1 database**
   - Variable name: `DB` (대문자, 정확히)
   - D1 database: `bareunbp` 선택 → **Save**
3. 같은 Settings에서 **Variables and Secrets** → **Add**
   - Type: **Secret**
   - Variable name: `ADMIN_KEY`
   - Value: 영문·숫자를 섞은 20자 이상 비밀번호. **관리자 콘솔 로그인 키**입니다. 안전한 곳에 메모해 두세요.
   - **Save**
4. (선택) 의료진 감수자에게 줄 별도 키가 필요하면 같은 방법으로 `REVIEWER_KEY`(Secret)를 하나 더 추가합니다. 감수자는 이 키로 로그인해 답변 검토와 감수 기록만 할 수 있습니다.
   - 회원 로그인을 위해 따로 넣을 값은 없습니다. 로그인 쿠키에 서명하는 비밀값은 사이트가 처음 한 번 스스로 만들어 데이터베이스에 보관합니다. (직접 정하고 싶으면 `SESSION_SECRET`이라는 Secret을 추가하면 그 값을 씁니다. 값을 바꾸면 모든 회원이 로그아웃됩니다.)
5. **Deployments** 탭 → 최신 배포 오른쪽 **⋯** → **Retry deployment** (바인딩을 반영하려면 한 번 재배포)

### 3-3. 확인
- 브라우저에서 `https://bareunbp.pages.dev/api/health` 를 열어 `"db":true`, `"admin_key":true` 가 보이면 연결된 것입니다.
- `https://bareunbp.pages.dev/admin/` 에 들어가 이름과 ADMIN_KEY로 로그인되면 관리자 콘솔 준비가 끝난 것입니다.
- 사이트의 커뮤니티 페이지에서 질문을 하나 보내보고 "접수됐습니다"가 뜨면 완료입니다.
- 오른쪽 위 **로그인 → 회원가입**으로 시험 계정을 하나 만들어 자유게시판에 글이 써지는지 확인합니다. 이미 D1을 연결해 둔 사이트라면 새로 할 일은 없습니다. 회원·게시판용 표는 첫 접속 때 자동으로 추가됩니다.

## 4단계. 도메인 연결 (선택)

1. `bareunbp` 프로젝트 → **Custom domains** → **Set up a custom domain** → 도메인 입력
2. 도메인이 Cloudflare에 등록돼 있으면 자동으로 연결됩니다. 다른 곳에서 샀다면 안내되는 CNAME 값을 도메인 업체 DNS에 넣으면 됩니다.
3. **도메인이 확정되면** 사이트 안의 주소 표기(`https://bareunbp.com`, canonical·sitemap·OG 태그)를 실제 도메인으로 바꿔야 검색 엔진에 정확히 잡힙니다. 사이트 동작에는 영향이 없지만 **검색엔진 등록 전에는 꼭 바꿔야** 합니다(sitemap.xml·rss.xml 주소가 이 값으로 만들어집니다). 바꿀 때는 파일 전체에서 `https://bareunbp.com` 을 실제 주소로 치환하면 됩니다(요청 주시면 일괄 교체해 드립니다).

## 관리자 콘솔 (`/admin/`)

주소: `https://(사이트 주소)/admin/` — 검색엔진에 노출되지 않고, 사이트 어디에도 링크가 없습니다.
로그인할 때 **처리자 이름**과 **접속 키**(ADMIN_KEY 또는 REVIEWER_KEY)를 넣습니다. 이름은 모든 처리 기록에 남습니다. 로그인은 12시간 유지되며, 키를 8번 틀리면 10분 동안 막힙니다.

| 메뉴 | 하는 일 |
|---|---|
| 대시보드 | 새 질문·문의·팩트체크 요청 수, 감수 진행률, 최근 14일 방문, 많이 본 페이지, 사이트 검색어, 유입 경로, 도구 이용(기록 저장 → 리포트 열람 → 인쇄) |
| KPI 대시보드 | 기간(오늘·7일·30일·90일·1년)별 방문자·신규·세션·페이지뷰·방문당 페이지·평균 체류시간·이탈률·완독률, 클릭·공유·저장·검색·회원·게시글, 몰 노출·클릭·클릭률·구매 건수·구매전환율·수익·1천 PV당 수익. 인기 정보 TOP10, 유입 경로·기기, 상품별 성과, 페이지별 표(CSV) |
| 바른혈압몰 | 쿠팡 파트너스 월별 실적 입력(클릭·구매·취소·금액·수익), 상품별 노출·클릭, 기본 상품 숨기기, 상품 추가·수정·삭제 |
| 질문·경험담 | 접수 → 작성 중 → 감수 요청 → 게시/숨김. 답변 틀 6종, 관련 글 링크 넣기, 금칙어 실시간 점검, 공개 화면 미리보기, 질문 속 연락처·이메일 가리기(원문은 내부 보관) |
| 문의·신청 | 기관 협력·가족 기능 신청을 신규 → 연락함 → 진행 중 → 완료/보류로 관리, 내부 메모, CSV 내려받기, 개인정보 파기 |
| 팩트체크 요청 | 접수 → 검토 중 → 발행/반려/중복, 발행한 팩트체크 글 연결 |
| 게시판 관리 | 자유게시판의 글·댓글·신고를 한곳에서 처리. 숨김(사유 선택)·다시 보이기·삭제, 공지 쓰기와 상단 고정. 서로 다른 회원 5명이 신고한 글은 자동으로 임시 숨김되어 여기서 확인을 기다립니다 |
| 회원 | 회원 목록과 검색, 이용 정지·해제, 내부 메모, 임시 비밀번호 발급(등록 이메일로 본인 확인이 된 경우에만), 강제 탈퇴. 비밀번호는 운영자에게도 보이지 않습니다 |
| 영상 관리 | ‘영상으로 배우기’에 영상 추가. 유튜브 주소를 붙여넣고 제목·출처·분류를 적으면 5분 안에 페이지에 나타납니다. 공식 기관 채널의 영상만 올립니다 |
| 콘텐츠·감수 | 건강정보·음식·팩트체크 85편의 감수 상태(감수 예정/수정 필요/감수 완료/재감수 도래). 승인 + 실명 공개 동의로 기록하면 공개 화면의 “의료진 감수 예정”이 “감수 완료 · 이름 자격”으로 5분 안에 바뀝니다 |
| 정정 이력 | 기록하면 공개 `정정 이력` 페이지에 5분 안에 표시. 삭제 없이 수정만 가능(수정 전 내용은 활동 기록에 보관) |
| 사이트 공지 | 모든 페이지 맨 위 공지 띠 문구·링크 변경 |
| 구독자 | 수신 중/수신거부 목록, 발송 도구용 CSV(구독자별 수신거부 링크 포함), 수신거부 처리·복구·파기 |
| 활동 기록 | 로그인·게시·삭제·내보내기 등 모든 관리자 작업 기록(수정·삭제 불가) |
| 시스템·데이터 | 연결 상태, 표별 건수, 보유기간 지난 데이터 파기, 전체 데이터 백업(JSON) |
| 운영 가이드 | 매일·매주·매월 할 일, 답변 원칙, 금칙어 표, 감수 원칙, 개인정보 처리 기준 |

**권한**: 관리자(ADMIN_KEY)는 모든 메뉴, 감수자(REVIEWER_KEY)는 질문 답변 검토·콘텐츠 감수 기록·정정 이력 보기만 할 수 있습니다.

**익명 이용 통계**: 페이지 주소, 유입 사이트 도메인, 사이트 검색어, 도구 이름(가입·글쓰기·공유·영상 재생 횟수 포함), 화면에 보인 시간과 스크롤 정도, 버튼·바깥 링크·몰 상품 클릭, 기기 종류(모바일/PC)만 날짜별 합계로 저장합니다. 방문자 수는 브라우저에 남긴 ‘오늘 왔는지’ 표시로 세며 식별 번호는 쓰지 않습니다. 혈압 수치·IP·쿠키 ID는 저장하지 않고, 브라우저의 추적 거부(DNT/GPC) 설정을 존중합니다. 자동 접속 프로그램(검색 로봇 등)은 세지 않습니다.

**보안 수칙**: 접속 키는 메신저로 보내지 말고 직접 전달하세요. 운영자가 바뀌면 Cloudflare에서 키 값을 바꾸고 재배포하면 기존 로그인은 모두 끊깁니다. 내려받은 CSV·백업 파일은 작업 후 지웁니다.

## 바른혈압몰 (쿠팡 파트너스)

- 주소 `/mall/`. 기록·복약 관리, 허리둘레·걷기, 덜 짜게 요리하기, 집에서 하는 운동 네 갈래로 21개 상품을 올려 두었습니다. 상품 목록은 `_src/gen/mall.py`에 있습니다.
- **올리지 않는 것**: 혈압계·체중계 같은 의료기기와 측정기, 건강기능식품·영양제, ‘혈압을 낮춘다’는 식으로 효능을 내세우는 제품. 사이트의 측정·기기 안내가 특정 제품 판매와 엮이지 않게 하려는 것입니다.
- **글과의 연결**: 글 본문에는 제휴 링크를 넣지 않습니다. 나트륨·운동·복약·체중 같은 관련 글 끝에만 ‘제휴 · 쿠팡 파트너스’라고 표시한 상자를 두고, 상자는 바른혈압몰로 이어집니다.
- **대가성 문구**: 몰 페이지 맨 위에 “이 페이지는 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.”를 둡니다. 지우지 마세요.
- **매월 할 일**: 쿠팡 파트너스 → 리포트에서 지난달 클릭·구매·취소·구매 금액·수익을 확인해 관리자 콘솔 **바른혈압몰**의 월별 실적에 옮겨 적습니다. 쿠팡은 구매 정보를 사이트로 보내 주지 않아서 구매전환율·수익은 이 입력값으로 계산합니다.
- **상품 추가**: 쿠팡 파트너스에서 상품을 검색해 링크를 만든 뒤, 관리자 콘솔 **바른혈압몰 → 상품 추가**에 단축 링크(`https://link.coupang.com/a/...`)와 상품 사진 주소를 붙여 넣으면 5분 안에 몰에 나타납니다.

## 회원 · 저장 · 자유게시판

- **회원가입** (`/account/signup/`): 아이디, 비밀번호, 닉네임만 받습니다. 이메일은 선택입니다. 이름·전화번호·생년월일은 받지 않고, **혈압 기록은 가입해도 계정에 저장하지 않습니다.**
- **비밀번호**: 이용자의 브라우저에서 변환한 값만 서버로 오고, 서버는 그 값을 다시 변환해 저장합니다. 원문은 어디에도 남지 않습니다.
- **비밀번호를 잊었을 때**: 메일 발송 기능이 없어서, 가입 직후 보여 주는 **복구 코드**로 회원이 직접 다시 정합니다(`/account/reset/`). 복구 코드도 없으면 회원이 등록 이메일로 문의하고, 운영자가 관리자 콘솔 **회원**에서 이메일이 일치하는지 확인한 뒤 임시 비밀번호를 발급해 회신합니다.
- **저장·공유**: 모든 글과 레시피에 ‘저장’과 ‘공유’ 버튼이 있습니다. 로그인하지 않으면 그 기기에만 저장되고, 로그인하면 계정에 옮겨져 다른 기기에서도 보입니다. 모아 보기는 `/my/`.
- **자유게시판** (`/community/board/`): 읽기는 누구나, 쓰기·댓글·공감·신고는 회원만. 분류는 자유·정보공유·생활습관·음식·식단·측정·기기·가족·돌봄·질문. 글은 꾸밈 없는 글자로만 표시되고 외부 링크는 걸리지 않습니다.
- **운영 기준**: `/policy/community.html`(게시판 운영 원칙)에 공개돼 있습니다. 약 조정 권유, 근거 없는 치료 효과, 광고, 개인정보 노출은 숨김 대상입니다. 하루 한 번 관리자 콘솔 **게시판 관리 → 신고** 탭을 확인해 주세요.
- **탈퇴**: 회원이 마이페이지에서 직접 합니다. 회원 정보는 바로 지워지고, 글은 본인 선택에 따라 함께 지우거나 ‘탈퇴한 회원’ 이름으로 남습니다.

## 매일 콘텐츠 발행

매일 아침 예약 작업이 글 한 편을 발행합니다. 운영 순서와 글쓰기 기준은 `_src/daily/RUNBOOK.md`에 있습니다.

- **주제 계획표**: `_src/daily/plan.json` — 요일별로 건강정보(월·목·금·일), 음식·식단(화), 팩트체크(수), 저염 레시피(토)를 돌려 가며 씁니다. 겨울·명절 같은 계절 주제는 기간을 정해 두었습니다.
- **글 파일**: `_src/daily/posts/YYYY-MM-DD-slug.py` 한 편에 파일 하나. 파일 이름의 날짜가 발행일이고, 그보다 이른 날에는 사이트에 나오지 않습니다(예약 발행).
- **흐름**: 아침 실행에서 전날 써 둔 오늘 글을 발행하고(오전 9시 30분 무렵 반영), 이어서 내일 글을 조사·작성해 예약해 둡니다. 예약된 글은 GitHub의 `_src/daily/posts`에서 미리 읽어 볼 수 있습니다.
- **자동 점검**: `python3 _src/gen/daily.py check 파일` — 출처 2개 이상, 사이트 안 링크 3개 이상, 자주 묻는 질문 3개 이상, 분량, 제목·요약 길이, 의료 광고성 표현(완치·특효·약 없이 등)과 기계적인 문체를 검사합니다. 통과하지 못하면 발행하지 않습니다.
- **현황 보기**: `python3 _src/gen/daily.py status`
- **검색엔진 알림**: 글이 발행되어 `sitemap.xml`이 바뀌면 GitHub Actions(`.github/workflows/indexnow.yml`)가 2~3분 뒤 새 주소를 IndexNow로 네이버·빙에 알립니다. 열쇠 파일은 맨 위 폴더의 `8c8ac57610110c4bd3b762f728c2c8bc.txt`이며 지우면 안 됩니다.
- **글을 빼고 싶을 때**: 예약된 글은 `posts`에서 파일을 지우면 발행되지 않습니다. 이미 발행된 글을 내리려면 파일을 지우고 사이트를 다시 생성합니다.

## 검색엔진 등록 (오픈 직후 1회)

검색 노출은 등록 후 보통 수일~수주가 걸립니다. 도메인을 확정한 뒤에 하세요.

### 네이버 서치어드바이저
1. https://searchadvisor.naver.com 로그인 → **웹마스터 도구** → 사이트 등록에 `https://도메인` 입력
2. 소유확인 방식은 **HTML 태그**를 씁니다. (Cloudflare Pages는 `.html` 주소를 확장자 없는 주소로 옮기기 때문에 HTML 파일 방식은 실패할 수 있습니다.)
3. 태그의 content 값을 `_src/gen/base.py`의 `NAVER_VERIFY`에 넣고 다시 생성하면 모든 페이지에 들어갑니다. **bareunbp.com은 2026-11-16에 등록을 마쳤습니다.**
4. 왼쪽 메뉴 **요청 → 사이트맵 제출**: `https://도메인/sitemap.xml`
5. **요청 → RSS 제출**: `https://도메인/rss.xml`
6. **검증 → 웹 페이지 최적화**로 홈 주소를 한 번 점검합니다.

### 구글 서치 콘솔
1. https://search.google.com/search-console → 속성 추가 → **도메인** 방식에 도메인 입력
2. 안내되는 TXT 레코드를 Cloudflare 대시보드 → 도메인 → **DNS → Add record**(Type: TXT)에 붙여넣기 → 확인
3. **Sitemaps** 메뉴에 `sitemap.xml` 제출

### 다음(카카오)
https://register.search.daum.net 에서 사이트 URL을 등록합니다.

확인 코드를 메타 태그 방식으로 받으셨다면 코드를 알려주세요. 사이트 전체에 넣어 드립니다.

## 콘텐츠 수정

페이지는 `_src/gen/` 생성기로 만들어집니다. HTML 파일을 GitHub에서 직접 고칠 수도 있지만, 다음에 생성기로 다시 만들면 덮어써지므로 글 수정은 생성기에 반영하는 것이 원칙입니다(요청 주시면 반영해 드립니다). 고친 뒤에는 관리자 콘솔 **정정 이력**에 기록하세요.

### 레시피 구조화 데이터 (Google 레시피 검색)

레시피 페이지의 구조화 데이터는 `_src/gen/recipe_sd.py` 한곳에서 만들고 검사합니다.

| 구분 | 속성 | 바른혈압 처리 |
|---|---|---|
| 필수 | name, image | 항상 넣음. 완성 요리 사진이 없으면 공용 사진을 씀 |
| 권장 | description, author, datePublished, recipeYield, totalTime, recipeIngredient, recipeCategory, recipeCuisine, keywords | 항상 넣음 |
| 권장 | recipeInstructions(HowToStep의 text·name·url) | 단계마다 제목(name)과 페이지 안 위치 `#step-N`(url)을 넣음 |
| 권장(실제 값만) | nutrition, video, aggregateRating, 단계 사진 | 확인된 값이 없으면 넣지 않음. Search Console에 ‘심각하지 않은 문제’로 남아도 검색 노출에는 지장 없음 |

- 새 레시피의 조리 단계는 `("단계 제목", "설명")` 형식으로 씁니다. 제목이 없으면 매일 발행 점검과 사이트 생성이 멈춥니다.
- **완성 요리 사진 넣기**: 직접 찍은 사진을 GitHub 웹에서 `assets/img/recipes/<레시피 주소>.jpg`로 올리면(예: `assets/img/recipes/bibimbap-light.jpg`) 다음 빌드부터 그 레시피 화면 위쪽과 구조화 데이터 image에 자동으로 쓰입니다. 가로 1200px 이상을 권장합니다.
- 점검: `check_site.py`가 레시피마다 필수·권장 속성, 단계 제목·위치, 화면 표시 여부를 확인합니다.

사이트 주소는 확장자 없는 형태(`/info/reading-numbers`)가 표준입니다. Cloudflare Pages가 `.html` 주소를 자동으로 이 형태로 옮기기 때문에, canonical·sitemap·내부 링크도 같은 형태로 맞춰 두었습니다.
